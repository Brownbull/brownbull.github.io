Property attributes at four levels

The first way of coding four attribute sets from property data (by property, state, consumer, and consumer × property) grouped rows by consumer and ran if-else functions over them, and it was very slow. I built a feature framework in Python that the team switched to: features are defined in files, loaded into memory and computed on the fly at each aggregation level, with columnar pandas/NumPy operations instead of row groups and flags as bitwise operations on data encoded as numbers instead of string checks. That rework is where the aggregation speed-up in Work history came from. I implemented and deployed it, coordinated with the AWS data team on loading property records across North America to validate it, and worked with data science on the model inputs and with marketing on specs and data dictionaries.

Where: Experian, 2023 · no code to show

  • Python
  • pandas
  • NumPy
  • AWS

Compute only what the requested outputs need

Before, every attribute, member and filter was computed at every level, and each function received whole records, such as every field of every credit trade. In the same framework I added a dependency tree built from the output attributes requested: it works out which inputs and intermediate attributes are needed, runs the functions in dependency order without repeating any, and passes each one only the fields it uses; each level appends only what it produces to the output.

Where: Experian, 2023 · Property Attributes

  • Python

Numbers misread between AIX and Linux

Many cross-platform differences traced back to C code that converted numbers between AIX (big-endian) and Linux (little-endian) machines and misread one data type. We fixed it as a team with an internal conversion table that accounts for both byte orders. My part: I found the discrepancies, helped trace the cause and design the fix, then deployed it and verified the results; a teammate wrote the code change.

Where: Experian

  • C
  • AIX
  • Linux

A memory allocation that overflowed its integer type

A memory allocation whose size overflowed the integer type in the function's signature wrote over other memory during mainframe batch (JCL) runs. As a team we traced it with mainframe debugging tools and fixed it by capping each allocation and requesting a second block, or allocating more statically. My part: I found it, helped trace it and design the fix, then deployed it and verified it; a teammate wrote the code change.

Where: Experian

  • IBM mainframe
  • JCL

A 3D graph to trace an attribute back

Tracing where an attribute difference could come from meant following its logic by hand from input to output, so I wrote Python scripts that parse the attribute definition files and draw each attribute's chain, through members and filters back to the raw input fields, as an interactive 3D dependency graph (Plotly, igraph), with each definition on hover and a view narrowed to chosen attributes. Built for my own debugging; a colleague added setup steps and a config file, and the team used it afterwards.

Where: Experian, 2018

  • Python
