Gabe Suite

Gabe Suite es el kit de Claude Code con el que desarrollo mis propios proyectos. Sus skills son instructivos en Markdown, algunos con scripts de apoyo, que llevan al modelo por plan, test que falla, código, revisión, commit y push, y dejan el estado del proyecto en archivos planos dentro de .kdbp/. En un proyecto configurado con /gabe-init, nueve scripts de hook vigilan la sesión. Siete solo imprimen avisos. Dos pueden bloquear: uno cuando un paso del plan se marca como terminado sin su prueba, y otro cuando un push al ambiente final no pasó por la revisión previa.

Cómo está construido

Cómo funciona

  • Cada paso del ciclo es una skill: un instructivo en Markdown (SKILL.md, a veces con scripts de apoyo) como /gabe-plan, /gabe-red o /gabe-commit. Claude Code carga el texto completo de una skill solo cuando se la llama, ya sea con su comando o porque el modelo la elige para la tarea. Cinco skills solo se pueden iniciar a mano. Al 22 de septiembre de 2026, la rama pública main tiene 28 skills y la rama de trabajo tiene 30.
  • El estado del proyecto vive en archivos planos dentro de .kdbp/: PLAN.md con su espejo en JSON, PENDING.md para el trabajo diferido, DECISIONS.md y LEDGER.md como índice de sesiones. Una sesión nueva retoma desde esos archivos, no desde el historial del chat.
  • /gabe-init agrega 9 scripts de hook a la configuración de usuario de Claude Code, repartidos en 5 eventos: inicio de sesión, prompt, antes de usar una herramienta, después de usarla y cierre. En una carpeta sin .kdbp/ no hacen nada. Siete de ellos solo agregan contexto o un aviso. Por ejemplo, editar código antes de que existan los tests que fallan genera un aviso, no un bloqueo.
  • Dos hooks pueden bloquear con exit 2. plan-proof-guard corre después de editar el plan y rechaza un paso marcado como terminado si falta su archivo de prueba o su commit red/green. Para entonces la edición ya quedó escrita, así que el modelo recibe un error que tiene que corregir. push-gate-guard solo actúa en proyectos que declaran más de un ambiente. Detiene un push al ambiente final, y cualquier push que no pueda probar que es seguro, salvo que /gabe-push haya registrado un escaneo de salud y la respuesta de continuar para el commit actual. Una variable de emergencia deja pasar el push con una advertencia.
  • Los 9 hooks tienen tests de fixtures en shell que verifican que cada uno se dispara cuando corresponde y se queda callado cuando no. Un generador en Python arma el sitio estático de documentación que muestran las capturas. En ese sitio, el ledger de cumplimiento clasifica las 119 reglas que declara la suite. Ese ledger es una auditoría escrita de julio de 2026, no un cálculo, y en ese momento encontró 19 reglas con un control que realmente se ejecuta. El mismo sitio lista 13 verificadores que todavía no tienen tests.
  • Trae dos servidores MCP propios: gabe-map expone el mapa versionado del código como 18 herramientas de consulta, y gabe-kdbp expone el estado del ciclo en .kdbp/ como 7 herramientas de solo lectura. Los dos usan solo la biblioteca estándar de Python por stdio, comparten una capa JSON-RPC y se registran una vez por usuario. Sus herramientas se le muestran al agente en cada sesión, así que consulta el mapa en vez de volver al grep.
