Proyecto personal · parte de Gabe Suite

Gabe Command Center

Un sitio de documentación que un proyecto genera sobre sí mismo: trabajo abierto, entidades del dominio, endpoints, modelos de datos y resultados de tests, leídos del código, de los reportes de tests guardados en el repo, de git y de los archivos de plan. Lo construí dentro de Gastify, lo pasé a Gabe Suite y lo uso en dos de mis repos privados. No hay demo publicada; las capturas son del build de Gastify, abierto como archivos locales.

Cómo está construido

Cómo funciona

  • En cada build lee los archivos del propio proyecto: rutas FastAPI, modelos SQLAlchemy y schemas Pydantic leídos con el módulo ast de Python, los junit XML que dejó en el repo la última corrida de tests registrada, el historial de git y los archivos de plan en .kdbp/ (PLAN, PENDING, LEDGER). Nunca corre los tests por su cuenta.
  • El generador es Python, solo con imports de la biblioteca estándar y sin llamadas a un LLM. Llena plantillas HTML fijas y escribe archmap.json, un mapa JSON ordenado del código que se versiona junto a las páginas, así que el diff de un pull request muestra qué cambió en la arquitectura. El único texto mantenido a mano es una ficha Markdown por entidad, redactada con una skill de Claude Code y con un sello que le pongo al revisarla.
  • El tablero es una proyección, no un gestor de tareas: ahí nada se arrastra ni se guarda, y una tarjeta cambia solo cuando cambian los archivos de los que sale. Cada una muestra su esfuerzo, cuánto tiempo lleva abierta y el comando que la inicia.
  • Después de cada build, un control de enlaces hace fallar la corrida si falta un link, un ancla o un recurso. En el CI de Gastify, un pull request que toca el centro lo reconstruye sobre un checkout limpio y corre ese control.
  • gabe-map, un servidor MCP pequeño en el mismo repo (Python con biblioteca estándar, por stdio), convierte el mapa versionado en herramientas: Claude Code puede preguntar a qué modelos llega un endpoint o qué entidad es dueña de un archivo en vez de hacer grep. Lo hice servidor MCP porque los hooks, las instrucciones y las convenciones no bastaban para que los agentes dejaran de volver al grep: las herramientas de un servidor MCP se le anuncian al agente en cada sesión, así que usar el mapa ya no depende de que se acuerde.
