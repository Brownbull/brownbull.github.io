Gabe Suite

Gabe Suite is the Claude Code toolkit I build my own projects with. Its skills are Markdown playbooks, some with helper scripts, that walk the model through plan, failing test, code, review, commit and push, and keep the project's state in plain files under .kdbp/. In a project set up with /gabe-init, nine hook scripts watch the session. Seven only print reminders. Two can block: one when a plan step is marked done without its proof, and one when a push to the final environment skipped the release check.

How it is built

How it works

  • Each step of the loop is a skill: a Markdown playbook (SKILL.md, sometimes with helper scripts) such as /gabe-plan, /gabe-red or /gabe-commit. Claude Code loads a skill's full text only when it is called, either by its slash command or when the model picks it for the task. Five skills can only be started by hand. As of 22 September 2026 the public main branch has 28 skills and the working branch has 30.
  • Project state lives in plain files under .kdbp/: PLAN.md with a JSON mirror, PENDING.md for deferred work, DECISIONS.md, and LEDGER.md as a session index. A new session picks up from these files, not from chat history.
  • /gabe-init adds 9 hook scripts to Claude Code's user settings, spread over 5 events: session start, prompt, before a tool call, after a tool call, and stop. In a folder without .kdbp/ they do nothing. Seven of them only add context or a warning. For example, editing source code before the failing tests exist gets a warning, not a block.
  • Two hooks can block with exit 2. plan-proof-guard runs after a plan edit and rejects a step marked done when its proof file or its red/green commit is missing. The edit has already been written by then, so the model gets back an error it has to fix. push-gate-guard only acts in projects that declare more than one environment. It stops a push to the final environment, and any push it cannot prove is safe, unless /gabe-push recorded a health scan and a 'proceed' answer for the current commit. An emergency flag lets a push through with a warning.
  • All 9 hooks have shell fixture tests that check each one fires when it should and stays silent when it should not. A Python generator builds the static docs site shown in the screenshots. On that site, the enforcement ledger sorts the 119 rules the suite states. The ledger is a written audit from July 2026, not a computed result, and at that point it found 19 rules with a check that actually runs. The same site lists 13 checkers that still have no tests.
  • Two small MCP servers of mine ship with it: gabe-map exposes a project's committed code map as 18 query tools, and gabe-kdbp exposes the workflow state in .kdbp/ as 7 read-only tools. Both are Python standard library over stdio, share one JSON-RPC layer and are registered once per user. Their tools are listed to the agent in every session, so it uses the map instead of falling back to grep.
