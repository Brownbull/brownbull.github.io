Side project · part of Gabe Suite

Gabe Command Center

A documentation site a codebase builds about itself: open work, domain entities, endpoints, data models and test results, read from the code, the committed test reports, git and the plan files. I built it inside Gastify, moved it into Gabe Suite, and use it in two of my private repos. There is no hosted demo; the screenshots are Gastify's build, opened as local files.

How it is built

How it works

  • At build time it reads the project's own files: FastAPI routes, SQLAlchemy models and Pydantic schemas parsed with Python's ast module, the junit XML left in the repo by the last recorded test run, git history, and the plan files in .kdbp/ (PLAN, PENDING, LEDGER). It never runs the tests itself.
  • The generator is Python with standard-library imports only and no LLM calls. It fills fixed HTML templates and writes archmap.json, a sorted JSON map of the code committed next to the pages, so a pull request diff shows what changed in the architecture. The only hand-maintained text is one Markdown card per entity, written through a Claude Code skill and stamped when I review it.
  • The board is a projection, not a tracker: nothing on it can be dragged or saved, and a card moves only when the files it comes from change. Each card shows its effort, how long it has been open and the command that starts it.
  • After every build, a crawl gate fails the run on any broken link, anchor or asset. In Gastify's CI, a pull request that touches the center rebuilds it on a clean checkout and runs that gate.
  • gabe-map, a small MCP server in the same repo (Python standard library, stdio), turns the committed map into tools, so Claude Code can ask which models an endpoint reaches or which entity owns a file instead of grepping. I made it an MCP server after hooks, instructions and conventions failed to stop agents from defaulting to grep: an MCP server's tools are listed to the agent in every session, so using the map no longer depends on the agent remembering it.
