Personal agent platform

A private set of 22 Claude Code agents I built for my own paperwork, research and side projects. Each one owns a domain and carries its own knowledge and state; most run their cases through the same outline: intake, analysis, a draft and my review. This page describes how it is put together.

What it is for

Every agent covers one domain I actually deal with, so the work that used to be a blank page starts from a method, a knowledge base and a record of what happened last time.

  • Paperwork with rules I keep forgetting: tax questions and filings, legal correspondence, the audit documentation of a rural drinking-water committee, and the administration of a shared land plot.
  • Money and home: household spending analysis, property equipping and budgets, vehicle diagnosis and maintenance.
  • My own work: this job search, editorial review before publishing, market and product research, content production, and a knowledge-absorption agent that reads repositories and papers and turns them into notes I can use.
  • Governance: a meta-agent that creates new agents to a shared quality checklist and has formally audited several of them, so they stay consistent as the set grows.

Outputs are drafts for me to check. The agents write files, and nothing is published or sent without my confirmation; I decide, sign and send.

How it is built

  • One YAML definition per agent. Role and voice, a menu of commands (8 to 31 per agent, more than 400 across the set), the files to load when a session starts, and checks to run before and after a command.
  • A sidecar next to it. The working method, my preferences, a curated knowledge base loaded selectively rather than all at once, dynamic state (open cases, pipelines), and instincts: rules of thumb, most seeded from best practice and a few added after real cases, each with a starting confidence value and, in several agents, a rule (not yet applied) for raising or lowering it when a call turns out right or wrong.
  • A case folder per job, dated and owned by one agent, holding intake, analysis and deliverables. A dashboard file lists every open case across agents.
  • Guardrails in the definition, not in my memory. Escalation rules (in 15 of the 22 agents), written as prose instructions, that tell the agent to stop and hand the decision to me or refer it to a professional, phrasings it may not use, a requirement to label each figure as verified or inferred and to name its source, and a rule that deliverables are written for my review and nothing is published or sent without my confirmation.
  • A shared execution contract that every agent follows: cite evidence, run the check before claiming something passed, and update the state file in the same session.

Limits

  • Internal use, one user, one machine. It is not a product and it is not multi-user.
  • The repository holds real personal and third-party material, so it stays private and nothing from it appears here.
  • There is no accuracy evaluation. The safeguard is that a person reads every output before it goes anywhere.
  • Counts as of September 2026: 22 agents, more than 400 commands (8 to 31 per agent). First commit January 2026.
